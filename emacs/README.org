#+title: flocal-guard

=flocal-guard= is an Emacs 28+ companion for local files synchronized by
=flocal=. It is an affordance and protection layer, not a flocal control
client: it has no commands to pair, start, stop, or synchronize shares.

* Install and enable

Put this directory on =load-path=, then enable the global mode:

#+begin_src emacs-lisp
(require 'flocal-guard)
(flocal-guard-mode 1)
#+end_src

The mode discovers shares with =flocal status --list --json=. Set
=flocal-guard-executable= to an absolute executable that resolves to a regular
non-symlink file when the normal discovery does not find it. The command is
read-only: it never starts a daemon.

* What it does

For an enabled share not known to be stopped, visiting buffers show an
=FLOCAL:= modeline item. =M-x flocal-guard-status= shows the same live or
stored cache without offering controls. The cache expires after 15 seconds;
a modified buffer waits for a fresh status result instead of guessing that it
is outside a share.

On visit and after each successful save, the guard stores a SHA-256 hash of
the visiting buffer's normal serialized content. Before a guarded modified
save, it hashes the current disk file. An atomic replacement with identical
bytes is harmless and saves normally. A different disk version starts Ediff
with the user buffer as A and a private, read-only =DISK:= snapshot as B.
Writing A is allowed only while disk still equals that snapshot. Quitting Ediff
leaves the conflict pending, so the next save opens it again.

The guard refuses snapshots larger than =flocal-guard-max-conflict-bytes=
(1 MiB by default), and refuses to save when it cannot verify a regular local
file. This preserves the buffer and disk rather than silently choosing one.

This is best-effort accidental-clobber protection. Emacs cannot make the final
pathname write a filesystem compare-and-swap operation, so a concurrent writer
can still win a race after the final inspection and before the write.
